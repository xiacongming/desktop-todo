# 桌面待办便签 —— 开发提示词（v1 完整版）

> 用法：把本文档整体发给开发方（人或 AI），作为唯一需求依据。文末附一句话精简版。

---

## 0. 一句话版本

用 Electron 做一个 Windows 桌面悬浮待办便签：无边框半透明小卡片常驻桌面，可拖动可置顶，能快速新增待办、拖拽排序、勾选完成、完成项自动折叠归档、可设截止日期到点提醒、可切换背景皮肤；数据只存本地 JSON，开机自启，关掉重开内容与窗口位置都不丢。

---

## 1. 角色设定

你是一位长期做 Windows 桌面小工具的资深工程师，熟悉 Electron 主进程/渲染进程模型、无边框透明窗口、托盘与开机自启、本地数据持久化。你的判断标准是：**这个工具要能被人每天用上一整年而不厌烦**。所以优先保证启动快、内存低、交互零摩擦、数据绝不丢。

---

## 2. 目标与非目标

**目标**
- 打开电脑就在，随手记一句话不超过 3 秒
- 一眼看清「还没做」和「做完了」
- 关掉、重启、断电，数据一条不少

**本次明确不做（非目标，避免范围膨胀）**
- 云同步 / 多设备 / 账号体系
- 多人协作、分享
- 子任务嵌套、重复任务（每月/每周循环）
- 复杂标签体系、看板视图、甘特图
- 移动端 App

---

## 3. 技术约束

| 项 | 要求 |
|---|---|
| 框架 | Electron（最新稳定版）+ 原生 HTML/CSS/JS 或 Vite + 任一轻量框架 |
| 打包 | electron-builder，产出 Windows x64 安装包，额外提供免安装 portable exe |
| 安全 | `contextIsolation: true`、`nodeIntegration: false`，渲染进程只能通过 preload 暴露的白名单 IPC 通信 |
| 依赖 | 保持精简，UI 组件库能不用就不用，避免包体膨胀 |
| 数据 | 本地 JSON 文件，位置 `app.getPath('userData')/todos.json` |

---

## 4. 窗口与系统行为

1. **无边框透明窗口**：`frame: false` + `transparent: true`，圆角 + 柔和投影，边缘 1px 半透明描边。不允许出现系统标题栏。
2. **拖动**：顶部标题条设 `-webkit-app-region: drag`，条上的按钮区设 `no-drag`，拖窗时不会误触按钮。
3. **置顶**：默认 `alwaysOnTop: true`，标题条上有图钉按钮可切换；切换状态要持久化。
4. **位置记忆**：保存 `x / y / width / height`。启动时先校验坐标是否落在当前任一显示器可见范围内——若不合法（例如拔掉了副屏），回落到主屏居中，绝不允许窗口出现在屏幕外。
5. **开机自启**：用 `app.setLoginItemSettings({ openAtLogin })`，设置面板里给开关。首次启动不要静默开启，先提示用户确认。
6. **托盘**：托盘图标 + 右键菜单（显示/隐藏、置顶、皮肤、开机自启、退出）。点窗口的「×」是**隐藏到托盘**而非退出进程；只有托盘菜单里的「退出」才真正结束进程。
7. **单实例**：重复启动时唤起已有窗口，不新开第二个。
8. **不占任务栏**：`skipTaskbar: true`（如果体验有问题，改成一个可配置项）。
9. **全局快捷键**：`Ctrl + Alt + T` 唤起/隐藏窗口，可在设置里关闭。

## 5. 数据模型

```json
{
  "version": 1,
  "settings": {
    "alwaysOnTop": true,
    "skin": "paper",
    "autoLaunch": true,
    "collapseDone": true,
    "globalHotkey": true,
    "window": { "x": 1200, "y": 80, "width": 320, "height": 420 }
  },
  "todos": [
    {
      "id": "uuid-v4",
      "text": "把周报发给张工",
      "done": false,
      "pinned": false,
      "order": 1024,
      "dueAt": "2026-10-28T09:00:00+08:00",
      "remindedAt": null,
      "createdAt": "2026-10-27T14:30:00+08:00",
      "completedAt": null
    }
  ]
}
```

**持久化要求（这条最容易被忽略，必须做到）**
- **原子写入**：先写 `todos.json.tmp`，`fsync` 后再 `rename` 覆盖正式文件。禁止直接覆写正式文件。
- **备份**：每次写入前把上一版复制为 `todos.bak.json`（只留最近 1 份）。
- **容错启动**：主文件解析失败 → 自动读备份；备份也失败 → 以空列表启动，并在界面上给一条明确提示，**不允许崩溃或静默清空**。
- `order` 用 1024 步长递增，便于在两项之间插入时取中间值；间隔耗尽时做一次全量重排。

## 6. 功能规格（含验收标准）

### 6.1 新增待办
- 窗口底部固定一个输入框，任何状态下都可直接输入。
- `Enter` 提交，提交后输入框保持聚焦并清空，可以连续录入（验收：连按三次 Enter 得到三条，中间不需要再点输入框）。
- `Esc` 清空当前输入并失焦。
- 空白或纯空格不提交。
- 单条上限 500 字，超出时给出提示而不是静默截断。
- 新增项插入到「未完成」列表**顶部**（随手记的心理模型是"刚想到的最近"）。

### 6.2 排序
- **拖拽排序**：按住条目拖动，拖动中有明确的半透明跟随与落位占位线，松手落位并立即持久化。
- **置顶（pin）**：pin 后的条目恒定排在未完成区最前，pin 区内部可互相排序；未 pin 的条目不能拖进 pin 区（反之亦然）。
- 排序不因重启、完成/取消完成而错乱。

### 6.3 完成与归档
- 左侧圆形勾选框，点击切换完成状态；勾选后有约 200ms 的下沉动画进入「已完成」区。
- 「已完成」区默认折叠，标题显示为 `已完成 (n)`，点击展开/收起。
- 已完成条目：文字加删除线 + 60% 透明度，可再次点击勾选框撤回未完成区，**并回到它原来的排序位置**。
- 提供「清空已完成」，需二次确认；清空后 5 秒内支持 `Ctrl + Z` 撤销。
- 单条删除：hover 出现删除图标；删除后底部浮出 toast，5 秒内可撤销。

### 6.4 截止日期与提醒
- 每条待办可选择性设置截止时间（右键菜单或 hover 出现的日历入口）。
- 视觉标记：**今天到期**橙色徽标，**已逾期**红色徽标，**未来日期**灰色小字（如 `10-30`）。
- 到点触发 Windows 系统通知（Electron `Notification`），同时窗口内该条目做一次高亮脉冲。
- 应用未运行时错过的提醒：启动后**合并成一条汇总通知**（例如"你有 3 项待办已逾期"），不要逐条刷屏。
- 每条只提醒一次，用 `remindedAt` 标记；用户手动改了截止时间则重置该标记。

### 6.5 皮肤切换
- 至少 5 套：`纸感米白` / `磨砂玻璃深色` / `淡蓝极简` / `暖黄便签` / `高对比暗黑`。
- 切换即时生效、无需重启，且重启后保持上次选择。
- 皮肤只通过 CSS 变量控制（背景、文字、次要文字、强调色、圆角、阴影、勾选框样式），不写死颜色。
- 每套皮肤下正文文字对比度不低于 4.5:1（WCAG AA）。

---

## 7. 交互细节

- 双击条目文字进入**行内编辑**，`Enter` 保存、`Esc` 取消。
- `Ctrl + Z` 撤销最近一次删除 / 清空已完成。
- 列表区独立滚动，头部（标题条）与底部（输入框）固定不动；窗口变矮时不出现整窗滚动条。
- 鼠标滚轮在列表区正常滚动，滚到边界不带动整个窗口。
- 空白态给一句轻提示：`今天还没有待办`。

---

## 8. 视觉规范

- 默认尺寸 320 × 420 px，圆角 14px，投影柔和（不要重投影，会显得廉价）。
- 字体：`"Segoe UI", "Microsoft YaHei", system-ui`。
- 字号：标题 14px / 正文 13px / 辅助信息 11px；行高 1.5。
- 布局自上而下：**标题条**（日期 + 图钉 + 皮肤 + 设置 + 收起）→ **未完成列表** → **已完成折叠区** → **输入框**。
- 动效克制：新增淡入、完成下沉、删除淡出，时长 150–220ms，`ease-out`；不做炫技动画。
- 未完成条目最小点击高度 32px，勾选框 18px，保证不误触。

---

## 9. 边界与异常

- 超长文本自动换行，最多显示 3 行，超出省略，hover 显示全文。
- 条目超过 200 条时滚动仍流畅（必要时虚拟滚动）。
- 系统 DPI 125% / 150% 缩放下布局不错位、不模糊。
- `todos.json` 被人为写坏、或磁盘只读时，程序不崩、不丢已有数据。
- 多显示器热插拔后窗口位置自动纠正。

## 10. 交付物

1. 完整可运行源码（含 `package.json`、preload、主进程、渲染进程）
2. `npm run dev` 可启动；`npm run build` 可产出 Windows 安装包 + portable exe
3. `README.md`：如何运行、如何打包、数据文件在哪、如何备份/迁移
4. 一个 `docs/数据格式说明.md`，说明 JSON 各字段含义，方便以后手改或迁移

## 11. 验收清单（自测必须全过）

- [ ] 连按三次 Enter 连续新增三条，无需重新点输入框
- [ ] 拖拽调整顺序后关闭程序再打开，顺序不变
- [ ] 勾选完成后落入「已完成 (n)」，展开可见；取消勾选回到原位置
- [ ] `Ctrl + Z` 能撤销刚才的删除
- [ ] 设一条 1 分钟后的提醒，到点弹出系统通知，且只弹一次
- [ ] 5 套皮肤全部可切换，重启后保持
- [ ] 拖到副屏 → 重启 → 位置不变；拔掉副屏再启动 → 窗口仍在主屏可见
- [ ] 开机/重启后自动出现在桌面
- [ ] 手动把 `todos.json` 改成乱码 → 重启不崩，能读备份或从空数据启动并提示
- [ ] 托盘「×」只是隐藏，托盘「退出」才结束进程
- [ ] 125% DPI 下布局正常

---

## 12. 建议开发顺序

1. 窗口骨架：无边框 + 透明 + 拖动 + 置顶 + 位置记忆
2. 数据层：读写 JSON、原子写入、备份、容错启动
3. 核心交互：新增 / 勾选 / 删除 / 行内编辑
4. 拖拽排序 + 置顶
5. 已完成折叠归档 + 撤销
6. 皮肤系统（CSS 变量化）
7. 截止日期 + 通知 + 错过提醒汇总
8. 托盘 + 开机自启 + 全局快捷键 + 单实例
9. 打包、DPI 与异常场景回归测试
